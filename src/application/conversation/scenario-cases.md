# Conversation Scenario Cases

Заполняй кейсы ниже. Один блок = один полный диалоговый сценарий.

## Как заполнять

- `id`: короткий уникальный идентификатор (`scn-001`, `late-phone-01`).
- `description`: что проверяем в этом сценарии.
- `messages`: последовательность входящих сообщений от клиента по шагам.
- `expected_replies`: ожидаемый ответ бота на каждый шаг (по порядку).
- Если на шаге бот должен промолчать, укажи `""` (пустая строка).
- `notes`: любые важные детали (режим, данные в БД, особые условия).

---

## Template

```yaml
- id: scn-001
  description: "Короткое описание сценария"
  messages:
    - "сообщение клиента 1"
    - "сообщение клиента 2"
  expected_replies:
    - "ответ бота 1"
    - "ответ бота 2"
  notes: "необязательно"
```
